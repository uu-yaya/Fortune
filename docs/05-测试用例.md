# 测试用例

- 文档版本：v3.0
- 更新日期：2026-03-08
- 适用版本：当前仓库主线

## 1. 测试范围

当前主线测试范围包括：

1. 鉴权与账户
2. 聊天主链路
3. 时间一致性
4. 资料抽取与身份事实回答
5. provider 降级与回退
6. 并发资料写入
7. 资料/媒体联动回归
8. 知识入库基础能力

## 2. 环境矩阵

- E1：本地直连 `http://127.0.0.1:8000`
- E2：Docker Compose `http://127.0.0.1:8001`

基础前提：

- MySQL、Redis 可用并已初始化
- `.env` 已配置必要密钥
- 开发环境可临时打开 `SMS_DEBUG_CODE_ENABLED=true`

## 3. 核心功能用例

### 3.1 鉴权与账户

| 用例ID | 用例名称 | 预期结果 |
|---|---|---|
| TC-AUTH-001 | 发送验证码成功 | 返回 `ok=true`，含 `ttl_seconds` |
| TC-AUTH-002 | 非法手机号发码失败 | `400` |
| TC-AUTH-003 | 冷却期重复发码 | `429` |
| TC-AUTH-004 | 验证码注册成功 | 返回 `user_id`、`short_account` 并设置 Cookie |
| TC-AUTH-005 | 账号密码登录成功 | 返回 `ok=true` 并设置 Cookie |
| TC-AUTH-006 | `GET /auth/me` 已登录成功 | 返回用户信息与 profile |
| TC-AUTH-007 | 未登录访问 `/auth/me` | `401` |
| TC-AUTH-008 | 密码重置成功 | 新密码可登录 |
| TC-AUTH-009 | 退出登录 | 清理 Cookie |

### 3.2 聊天主链路

| 用例ID | 用例名称 | 预期结果 |
|---|---|---|
| TC-CHAT-001 | 未登录聊天 | `401` |
| TC-CHAT-002 | 空问题 | 返回引导文案 |
| TC-CHAT-003 | 问候快捷回复 | 命中 fast reply |
| TC-CHAT-004 | 时间快捷回复 | 返回当前日期/星期/时间 |
| TC-CHAT-005 | 命理资料缺失拦截 | 提示补齐资料 |
| TC-CHAT-006 | 历史资料融合 | 不重复追问已提供资料 |
| TC-CHAT-007 | `session_id` 兼容字段无污染 | 实际仍按用户 UUID 维护会话 |
| TC-CHAT-008 | 上游异常时有友好降级 | 不暴露堆栈、不暴露工具名 |

### 3.3 身份事实问答

| 用例ID | 用例名称 | 预期结果 |
|---|---|---|
| TC-FACT-001 | `我叫什么` | 直接返回真实姓名或昵称 |
| TC-FACT-002 | `我的生日是？` | 直接返回生日，不出现“你的生日”污染 |
| TC-FACT-003 | `我的出生时间是？` | 直接返回出生时段 |
| TC-FACT-004 | `我的生日和时辰是什么？` | 一次性返回生日 + 时段 |

### 3.4 时间一致性

| 用例ID | 用例名称 | 预期结果 |
|---|---|---|
| TC-TIME-001 | 今天问法为单日窗口 | 不再扩成三天 |
| TC-TIME-002 | 近两天/本周/年度窗口正确 | 输出窗口与当前时间锚点一致 |
| TC-TIME-003 | 长周期问法不缩成三天 | 不出现 `这三天/最近三天/未来三天` |
| TC-TIME-004 | 年度问法带目标年份 | 包含正确年份 token |

### 3.5 资料抽取与持久化

| 用例ID | 用例名称 | 预期结果 |
|---|---|---|
| TC-PROFILE-001 | 生日归一化 | `2005年6月15日 -> 2005-06-15` |
| TC-PROFILE-002 | 时刻归一化 | `早上5:45 -> 05:45` |
| TC-PROFILE-003 | 姓名误识别过滤 | `我是谁` 不写入姓名 |
| TC-PROFILE-004 | 偏好称呼写入 | `以后叫我阿星` 正确持久化 |
| TC-PROFILE-005 | 历史资料后补性别 | 后续轮次性别可合并入档案 |

### 3.6 并发与 provider 降级

| 用例ID | 用例名称 | 预期结果 |
|---|---|---|
| TC-CON-001 | 并发 partial update 不丢字段 | 同一用户不同字段并发写入后都保留 |
| TC-CON-002 | 并发昵称冲突遵守置信度 | 高置信旧值不被低置信新值覆盖 |
| TC-PROV-001 | 命理 provider timeout | 输出保守回退，不露内部错误细节 |
| TC-PROV-002 | 命理 provider quota | 命中降级与 breaker 逻辑 |
| TC-PROV-003 | 媒体 provider degraded | 返回稳定错误结构，不污染 profile |

## 4. 推荐自动化脚本

### 4.1 命理与通用回归

```bash
python3 scripts/fortune_regression.py --base-url http://127.0.0.1:8001 --max-cases 24
```

### 4.2 时间回归

```bash
python3 scripts/time_scope_regression.py --base-url http://127.0.0.1:8000 --timeout 80
python3 scripts/time_window_contract_test.py
```

### 4.3 资料与媒体联动回归

```bash
python3 scripts/regression_profile_media_issues.py
python3 scripts/preferred_name_pollution_regression.py --base-url http://127.0.0.1:8000
python3 scripts/identity_memory_regression.py --base-url http://127.0.0.1:8000
```

### 4.4 provider 降级与并发回归

```bash
python3 scripts/provider_degradation_regression.py
python3 scripts/profile_concurrency_regression.py --iterations 20
```

### 4.5 质量门禁

```bash
python3 scripts/quality_gate.py --base-url http://127.0.0.1:8001 --days 1
```

## 5. 发布前最小验收集

## 6. 维护规则

1. 新增路由或关键行为时，必须补对应测试用例 ID。
2. 回归脚本替代了旧人工验证后，应更新本文件，不再让 dated 报告承担“当前测试基线”。
3. 历史测试报告可保留，但测试入口与命令必须以本文件为准。
