## 3. 当前建议删除的文档类型

这些文件不应继续放在 `docs/` 里：

1. 生成型发版产物
   - `release-plan-*.md`
   - `release-diff-*.json`
2. 原始机器回归结果文件
   - `31-media-intent-routing-regression-2026-03-03.json`
3. 未来新增的临时脚本输出
   - 任何“仅供当次发版/当次回归”的 JSON、临时 Markdown、截图转存文本

删除原则：
- 能从 git 历史、CI 记录或脚本重新生成的文件，不放 `docs/`。
- `docs/` 只保留“长期阅读仍有价值”的内容。

## 4. 推荐阅读顺序

新成员建议按这个顺序建立认知：

1. `01-概要设计说明书.md`
2. `04-API接口文档.md`
3. `05-测试用例.md`
4. `用户使用手册.md`
5. `34-缘分居API接入与能力映射文档-2026-03-08.md`
6. 如需了解历史问题，再回看 `12/14/27/30/33`

## 5. 维护规则

1. 改接口、改数据结构、改部署方式时，必须同步更新 `01/04/05/06`。
2. 改用户可见交互时，必须同步更新 `用户使用手册.md`。
3. 改外部 provider 接入、额度判断、降级策略时，必须同步更新 `34-缘分居API接入与能力映射文档-2026-03-08.md`。
4. 新增一次性回归报告时，优先放脚本输出目录或 CI 产物，不默认写入 `docs/`。
5. 如果某份历史报告的价值已经被吸收到关键文档，应考虑删除原报告或移出主目录。
