# 概要设计说明书

- 文档版本：v3.0
- 更新日期：2026-03-08
- 适用范围：当前仓库主线实现（`server.py` + `mytools.py` + `media_service.py`）

## 1. 文档目标

本文档说明“吉伊大师”当前主线系统的总体架构、核心能力、关键链路和非功能要求，作为研发、测试、运维的统一基线。

## 2. 系统定位

系统面向中文命理陪伴场景，提供“登录鉴权 + 聊天问答 + 命理/占卜/解梦 + 时间一致性控制 + 质量门禁”的单体服务。

当前主线能力：

- 鉴权与账户
  - 手机验证码登录/注册
  - 账号密码登录
  - 忘记密码（验证码校验 + 密码重置）
- 智能问答
  - 问候与时间快捷回复
  - 命理主链路（八字、正缘、主题、方向、节奏类问题）
  - 占卜、解梦、星座问答
  - 通用 Agent 回退链路
- 资料与记忆
  - 自动抽取姓名、生日、出生时段、性别、称呼偏好
  - 会话按用户 UUID 绑定，避免前端传入 `session_id` 污染
  - 身份事实问答支持直接回答“我叫什么/我的生日/我的时辰”
- 质量治理
  - 时间窗口解析与一致性修正
  - 用户态输出脱敏（去资料回显、去工具名、去硬标签）
  - 质量指标采集与 `/quality/metrics` 聚合
- 外部能力
  - 缘分居：八字测算、每日一占、周公解梦
  - SerpAPI：可选搜索增强
  - Qdrant：本地网页知识向量库

## 3. 总体架构

系统采用“单体 FastAPI + 模板前端 + MySQL/Redis/Qdrant + 外部 provider”架构。

### 3.1 架构分层

- 接入层
  - 页面：`/`、`/index`、`/login`、`/register`、`/forgot-password`、`/reset-password`
  - API：`/auth/*`、`/chat`、`/quality/metrics`、`/add_urls`
- 应用层（`server.py`）
  - 鉴权与登录态管理
  - 资料抽取、融合与持久化
  - 路由判断（fast reply / dream / zodiac / fortune / agent fallback）
  - 输出清洗、时间校验、事实直答
  - 质量指标与路由观测
- 工具层（`mytools.py`）
  - `bazi_cesuan`
  - `yaoyigua`
  - `jiemeng`
  - 搜索与本地知识检索
- 数据层
  - MySQL：用户、资料、登录审计、密码重置日志
  - Redis：验证码、登录态、会话历史、特性开关、质量指标
  - Qdrant：向量化知识库

### 3.2 关键依赖

- FastAPI / Uvicorn
- LangChain
- MySQL 8
- Redis
- Qdrant（本地 path 模式）
- 外部模型：阿里百炼 OpenAI 兼容接口
- 外部命理能力：缘分居 API

## 4. 核心模块

- `server.py`：主路由、资料融合、问答编排、输出后处理、质量治理
- `config.py`：环境变量与开关
- `models.py`：LLM / Embedding 客户端工厂
- `mytools.py`：命理/占卜/解梦/搜索工具
- `media_service.py` / `dify_media_client.py`：媒体链路实现（当前仓库仍保留，但是否对外暴露接口以代码为准）
- `static/js/main.js`：前端聊天交互
- `sql/001_init_auth_schema.sql`：账号体系初始化
- `sql/002_media_tasks.sql`：媒体任务表结构

## 5. 核心业务流程

### 5.1 鉴权流程

1. 客户端调用 `POST /auth/send_code`。
2. 后端校验手机号与发送冷却时间，验证码写 Redis。
3. 客户端调用 `POST /auth/verify` 完成登录或注册。
4. 登录成功后写 Redis 登录态、MySQL 审计，并设置 `jiyi_auth_token` Cookie。

### 5.2 聊天主流程

1. 校验 Cookie -> Redis 登录态；未登录直接返回 `401`。
2. 把会话绑定到用户 UUID，而不是使用客户端传入的 `session_id`。
3. 从历史与本轮输入提取资料，合并写入 `user_profile`。
4. 依次尝试：
   - 时间/问候快捷回复
   - 解梦路由
   - 星座路由
   - 命理主链路
   - Agent fallback
5. 输出统一经过：
   - 用户态脱敏
   - 时间一致性修正
   - 最小回答契约补全
6. 质量指标写入 Redis，并可经 `GET /quality/metrics` 聚合查看。

### 5.3 身份事实问答流程

当用户直接问：

- 我叫什么
- 我的生日是？
- 我的出生时间是？
- 我的生日和时辰是什么？

系统优先走事实直答，不再先生成一段命理文本再脱敏，避免出现“你的生日你的出生时段”这类污染输出。

## 6. 部署形态

- 本地开发：`python server.py`，默认 `8000`
- Docker Compose：应用 `8001 -> 8000`、Redis `6380 -> 6379`、MySQL `3307 -> 3306`
- ECS：当前常规上线以 Docker Compose 为主；`password-only` 模式是专项部署方案，不是默认主线

## 7. 非功能要求

- 正确性：时间窗口、身份事实回答、资料融合必须优先于“文风”
- 可维护性：关键规则集中在 `server.py`，外部 provider 规则集中在 `mytools.py`
- 可观测性：错误日志、路由路径、质量指标可追踪
- 可降级性：外部 provider 异常时提供保守输出，不暴露内部工具名或堆栈
- 隐私：用户侧回复不直接回显完整生日、出生时段、内部工具名与函数名

## 8. 约束与风险

- `SMS_DEBUG_CODE_ENABLED` 只能用于开发环境
- 外部命理能力受缘分居额度与稳定性影响
- 部分历史文档仍记录了 `password-only` 首发流程，不代表当前默认部署方式
- `docs/` 中大量 dated 报告仅作历史参考，不应替代当前基线文档
