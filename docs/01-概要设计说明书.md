# 概要设计说明书

- 文档版本：v4.0
- 更新日期：2026-03-08
- 适用范围：当前仓库主线实现（`server.py` + `mytools.py` + `static/js/main.js`）

## 1. 文档目标

本文档说明“吉伊大师”当前主线系统的总体架构、核心能力、关键链路和非功能要求，作为研发、测试、运维的统一基线。

## 2. 系统定位

系统面向中文命理陪伴场景，提供“登录鉴权 + 聊天问答 + 命理/星座/生肖/姻缘/结婚/择时 + 解梦/占卜 + 时间一致性控制 + 质量门禁”的单体服务。

当前主线能力：

- 鉴权与账户
  - 手机验证码登录/注册
  - 账号密码登录
  - 忘记密码（验证码校验 + 密码重置）
- 智能问答
  - 问候与时间快捷回复
  - 综合命理主链路
  - 今日/明日/年运/财运/姻缘/正缘/结婚预测
  - 星座与生肖运势
  - 具体事项择时
  - 解梦、占卜、普通问答
- 资料与记忆
  - 自动抽取姓名、生日、出生时段、性别、称呼偏好
  - 会话按用户 UUID 绑定，避免前端 `session_id` 污染
  - 身份事实问答支持直接回答“我叫什么/我的生日/我的时辰/我的性别”
- 质量治理
  - 时间窗口解析与一致性修正
  - 用户态输出脱敏（去资料回显、去工具名、去硬标签）
  - 质量指标采集与 `/quality/metrics` 聚合
  - provider 级降级与回退观测
- 外部能力
  - 缘分居：八字、日运、年运、财运、星座/生肖、择时、姻缘、正缘、结婚预测、占卜、解梦
  - SerpAPI：可选搜索增强
  - Qdrant：本地网页知识向量库

## 3. 总体架构

系统采用“单体 FastAPI + 模板前端 + MySQL/Redis/Qdrant + 外部 provider”架构。

### 3.1 架构分层

- 接入层
  - 页面：`/`、`/index`、`/login`、`/register`、`/forgot-password`、`/reset-password`
  - API：`/auth/*`、`/chat`、`/quality/metrics`、`/add_urls`
- 应用层（`server.py`）
  - 鉴权与登录态管理
  - 资料抽取、融合与持久化
  - 路由判断（fast reply / dream / zodiac / fortune / agent fallback）
  - provider flag、merchant probe、降级与回退
  - 输出清洗、时间校验、事实直答、正缘图片 extra 组装
- 工具层（`mytools.py`）
  - birth-based 命理参数构造
  - 缘分居 provider 客户端
  - 占卜 / 解梦 / 搜索 / 本地知识检索
- 数据层
  - MySQL：用户、资料、登录审计、密码重置日志
  - Redis：验证码、登录态、会话历史、特性开关、质量指标、provider 探测缓存
  - Qdrant：向量化知识库

### 3.2 关键依赖

- FastAPI / Uvicorn
- LangChain
- MySQL 8
- Redis
- Qdrant（本地 path 模式）
- 外部模型：阿里百炼 OpenAI 兼容接口
- 外部命理能力：缘分居 API

## 5. 核心业务流程

### 5.1 鉴权流程

1. 客户端调用 `POST /auth/send_code`。
2. 后端校验手机号与发送冷却时间，验证码写 Redis。
3. 客户端调用 `POST /auth/verify` 完成登录或注册。
4. 登录成功后写 Redis 登录态、MySQL 审计，并设置 `jiyi_auth_token` Cookie。

### 5.2 聊天主流程

1. 校验 Cookie -> Redis 登录态；未登录返回 `401`。
2. 把会话绑定到用户 UUID，而不是使用客户端传入的 `session_id`。
3. 从历史与本轮输入提取资料，合并写入 `user_profile`。
4. 依次尝试：
   - 时间/问候快捷回复
   - 解梦路由
   - 星座/生肖路由
   - 命理主链路
   - Agent fallback
5. 命理场景按意图命中不同 provider：
   - `Bazi/yunshi`
   - `Bazi/weilai`
   - `Bazi/caiyunfenxi`
   - `Yuce/caiyun`
   - `Yuce/yinyuan`
   - `Yuce/zhengyuan`
   - `Yuce/jiehun`
   - `Gongju/zeshi`
   - `Bazi/cesuan`
6. 输出统一经过：
   - 用户态脱敏
   - 时间一致性修正
   - 最小回答契约补全
   - 可选 `extra.partner_portrait_image` 注入
7. 质量指标写入 Redis，并可经 `GET /quality/metrics` 聚合查看。

### 5.3 身份事实问答流程

当用户直接问：

- 我叫什么
- 我的生日是？
- 我的出生时间是？
- 我的性别是？

系统优先走事实直答，不再先生成命理文本再脱敏，避免资料污染式输出。

## 6. 部署形态

- 本地开发：`python server.py`，默认 `8000`
- Docker Compose：应用 `8001 -> 8000`、Redis `6380 -> 6379`、MySQL `3307 -> 3306`
- ECS：当前常规上线以 Docker Compose 为主；`password-only` 模式是专项部署方案，不是默认主线

## 7. 非功能要求

- 正确性：时间窗口、身份事实回答、资料融合优先于“文风”
- 可维护性：路由与治理规则集中在 `server.py`，provider 规则集中在 `mytools.py`
- 可观测性：错误日志、路由路径、provider 命中、质量指标可追踪
- 可降级性：外部 provider 异常时提供保守输出，不暴露内部工具名或堆栈
- 隐私：用户侧回复不直接回显完整生日、出生时段、内部工具名与函数名

## 8. 约束与风险

- `SMS_DEBUG_CODE_ENABLED` 只能用于开发环境
- 外部命理能力受缘分居额度、账号权限和接口稳定性影响
- 当前命理主链路默认要求姓名、出生日期、性别；出生时间是增强项，不是硬门槛
- `docs/` 中大量 dated 报告仅作历史参考，不应替代当前基线文档
