## 2. 通用接入规则

### 2.1 基础域名与请求方式

- 基础域名：`https://api.yuanfenju.com/index.php/v1/`
- 默认使用 `POST`
- 请求体默认采用 `application/x-www-form-urlencoded`

### 2.2 通用返回结构

当前统一按以下字段判断：

- `errcode`
- `errmsg`
- `notice`
- `data`

代码约定：

- `errcode == 0` 视为上游成功
- 其余情况进入 provider 级错误处理与必要的 merchant probe

### 2.3 birth-based 参数规则

以下接口共用同一套参数构造：

- `Bazi/cesuan`
- `Bazi/yunshi`
- `Bazi/weilai`
- `Bazi/caiyunfenxi`
- `Yuce/caiyun`
- `Yuce/yinyuan`
- `Yuce/zhengyuan`
- `Yuce/jiehun`

当前默认传入的关键参数：

- `api_key`
- `name`
- `sex`
- `type`
- `year`
- `month`
- `day`
- `hours`
- `minute`
- `lang`

当前约定：

- `lang` 默认 `zh-cn`
- `factor` 仅在部分接口显式传入
  - `Yuce/caiyun` 默认 `factor=1`
  - `Yuce/yinyuan` 默认 `factor=1`
- `province / city / longitude / latitude / timezone / zhen` 当前不启用

## 3. 项目内的真实业务关系

### 3.1 命理主链路不再只依赖 `Bazi/cesuan`

当前命理主链路按问题类型分流：

- 日运：`Bazi/yunshi`
- 年运：`Bazi/weilai`
- 财运：`Yuce/caiyun` 或 `Bazi/caiyunfenxi`
- 姻缘：`Yuce/yinyuan`
- 正缘：`Yuce/zhengyuan`
- 结婚预测：`Yuce/jiehun`
- 择时：`Gongju/zeshi`
- 兜底综合命理：`Bazi/cesuan`

因此：

- 命理健康度不能只看 `Bazi/cesuan`
- 但综合命理兜底仍然依赖 `Bazi/cesuan`

### 3.2 merchant probe 的作用

当上游出现：

- HTTP 非 200
- `errcode != 0`
- 可疑的额度/会员/密钥错误

系统会在 `merchant_probe_v1` 打开时，补查 `Free/querymerchant`，把错误区分为：

- 额度不足
- 会员过期
- 密钥异常
- 一般上游错误

## 4. 当前代码消费方式

### 4.1 birth-based 命理接口

当前项目不会把缘分居原始 JSON 直接透传给用户，而是：

1. 统一解析
2. 归一为通用 `BaziToolOutput` 风格字段
3. 再由 `server.py` 按场景渲染成吉伊语气的自然语言

### 4.2 `Zhanbu/yunshi`

当前用于：

- 星座问法
- 生肖问法

特点：

- 可根据已知生日自动推断星座或生肖
- 用户侧文案不展示“参考强度/参考分值”

### 4.3 `Gongju/zeshi`

只用于能映射到具体事项的择时问题，例如：

- 领证
- 搬家
- 出行
- 装修

当前用户侧文案会把黄历原始词串转成：

- 推荐日期
- 推荐理由
- 当天不宜叠加的事项

### 4.4 `Yuce/zhengyuan`

当前除了正文自然语言外，还会额外提取：

- `partner_portrait_image`

并挂到 `/chat` 返回的 `extra.partner_portrait_image`，供前端展示画像卡片。

## 5. 当前主要风险

1. 额度与账户状态风险
   - 不同接口的可用性并不完全等价
2. 探测偏差风险
   - 若只看单一接口，可能出现“探测 healthy，但业务问题不可用”
3. provider 文案泄露风险
   - 用户侧回复不应出现接口名、工具名或 provider 内部错误码
4. 结构化字段漂移风险
   - 上游字段变更时，解析器与 renderer 需要同步调整

## 7. 文档维护要求

当以下内容变化时，必须同步更新本文档：

1. 新增或下线缘分居接口
2. 更改主链路 provider 映射
3. 更改 merchant probe 或额度判断方式
4. 更改 birth-based 参数要求
5. 更改正缘画像、择时等用户侧渲染策略
