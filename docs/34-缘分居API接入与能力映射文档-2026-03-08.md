# 缘分居 API 接入与能力映射文档

- 更新日期：2026-03-08
- 文档定位：外部 provider 接入与风险说明，不是应用自身 API 文档

## 1. 当前接入现状

当前仓库实际接入了三类缘分居能力：

| 能力 | 官方接口 | 当前代码入口 | 当前用途 |
| --- | --- | --- | --- |
| 八字测算 | `v1/Bazi/cesuan` | `mytools.py:bazi_cesuan` | 命理主链路 |
| 每日一占 | `v1/Zhanbu/meiri` | `mytools.py:yaoyigua` | 占卜 / 摇卦 / 抽签 |
| 周公解梦 | `v1/Gongju/zhougong` | `mytools.py:jiemeng` | 解梦 |

环境变量：

- `YUANFENJU_API_KEY`

## 2. 项目内的真实业务关系

### 2.1 命理主链路真正依赖的是 `Bazi/cesuan`

这一点需要明确：

- 用户问综合运势、正缘、方向、主题、学业、事业、感情等命理问题时
- 真正打到的是 `Bazi/cesuan`

因此：

- 命理链路是否可用，应优先看 `Bazi/cesuan`
- 不能用 `Zhanbu/meiri` 的探测结果替代 `Bazi/cesuan` 的真实健康度

### 2.2 同一 API key 不等于所有接口额度完全等价

虽然当前只配置一个 `YUANFENJU_API_KEY`，但实际观察表明：

- `Zhanbu/meiri` 可用
- 不代表 `Bazi/cesuan` 仍有额度

这意味着：

- 线上健康探测不能只探 `Zhanbu/meiri`
- 与命理主链路直接相关的主动探测，应覆盖 `Bazi/cesuan`

## 3. 当前代码消费方式

### 3.1 `Bazi/cesuan`

当前项目会从上游响应中抽取并结构化消费：

- `bazi`
- `day_master` / `riyuan`
- `xiyongshen`
- `jishen`
- 五行强弱分布
- 感情 / 财运 / 命运 / 时间提示等字段

说明：

- 项目并不是把缘分居原始 JSON 直接透传给用户
- 用户侧回复会经过二次渲染、脱敏和自然化处理

### 3.2 `Zhanbu/meiri`

当前主要取其核心描述字段，用于占卜/抽签类回复。

### 3.3 `Gongju/zhougong`

当前通过关键词触发上游接口，处理梦境相关问答。

## 4. 当前主要风险

1. 额度与账户状态风险
   - 命理主链路最常见故障是 `Bazi/cesuan` 额度不足或上游异常
2. 探测偏差风险
   - 如果主动探测只测 `Zhanbu/meiri`，可能出现“探测 healthy，但命理实际不可用”的假健康
3. provider 文案泄露风险
   - 用户侧回复不应出现接口名、工具名或 provider 内部错误码
4. 结构化字段漂移风险
   - 上游字段变更时，`_parse_bazi_payload(...)` 可能需要同步调整

## 5. 建议的运维与开发策略

### 5.1 健康判断

优先级应为：

1. 真实命理请求是否成功
2. `Bazi/cesuan` 主动探测结果
3. 其他接口探测结果（如 `Zhanbu/meiri`）

### 5.2 故障分类

建议继续沿用项目内的 provider 分类：

- `timeout`
- `http_4xx`
- `http_5xx`
- `quota`
- `invalid_response`
- `network`

### 5.3 文档维护要求

当以下内容变化时，必须同步更新本文档：

1. 新增或下线缘分居接口
2. 更改主链路依赖接口
3. 更改健康探测方式
4. 更改 provider 降级、熔断或额度判断逻辑
