# 32-ECS 实机执行清单

- 更新日期：2026-03-08
- 用途：给运维或开发同学在 ECS 上手动执行 Compose 部署时作为核对清单
- 注意：本文保留的是“动作清单”，不再默认指向 password-only 首发

## 1. 通用上线清单

1. 登录服务器
2. 进入项目目录 `/opt/fortune-telling`
3. 拉取最新主干代码
4. 核对 `.env`
5. 执行 `docker compose up -d --build`
6. 查看容器状态与日志
7. 用 `/index` 做验活
8. 运行最小回归脚本

## 2. 推荐命令

```bash
cd /opt/fortune-telling
git fetch origin
git checkout main
git pull --ff-only origin main
docker compose up -d --build
docker compose ps
docker logs --tail=200 fortune-telling-numerology-1
curl -sS -o /dev/null -w "%{http_code} %{redirect_url}\n" http://127.0.0.1:8001/index
```

## 3. 建议补跑的回归

```bash
python3 scripts/time_scope_regression.py --base-url http://127.0.0.1:8001 --timeout 80
python3 scripts/quality_gate.py --base-url http://127.0.0.1:8001 --days 1
```

如本次改动涉及资料、媒体或 provider 降级，补跑：

```bash
python3 scripts/regression_profile_media_issues.py
python3 scripts/provider_degradation_regression.py
```

## 4. 仅在 password-only 场景额外执行

如果本次上线走的是 password-only 特殊模式，再额外执行：

1. password-only 网关配置
2. 预置账号脚本
3. `scripts/password_only_acceptance.sh`

## 5. 常见误区

1. 不要用 `/docs` 作为唯一健康检查
2. 不要只看容器 `Started` 就认为应用可用
3. 改 `.env` 后要重启容器，不能假设进程自动吃到新值
4. 如果要验证 API key 是否仍有效，需结合真实请求或主动 probe，而不是只看 `.env`
